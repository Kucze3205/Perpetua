# Agents hold no GitHub token

No agent session gets a GitHub token, not even the orchestrator: it writes the task graph to a file and the engine creates the issues. The epilogue never runs git inside the agent's working copy; it fetches the agent's commits as plain objects into a trusted checkout and pushes from there, with the token passed per command. We rejected giving the planner `gh` as the earlier loop did, and checkpoint pushes from the agent's shell: in both a hook or a config entry in a repository the agent controls could reach the token. The cost is that the engine owns the whole task-graph format and the agent cannot see GitHub state beyond the files the engine stages.
